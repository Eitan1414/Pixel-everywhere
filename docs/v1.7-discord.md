# Pixel Everywhere v1.7 — Discord Account Linking + Activity Center (first increment)

## What is implemented

### OAuth2 account association

A member signs into Pixel Everywhere, chooses **Compte Discord** from the v1.7 secondary menu, then:

1. Taps **Préparer la connexion Discord**. An authenticated request creates a short-lived, random one-time state on the server.
2. Taps **Ouvrir Discord pour autoriser**. The user consents on Discord's official site using OAuth2 with the `identify` scope only.
3. Discord redirects to the server callback, which verifies and consumes the state, exchanges the code for an access token server-side and fetches `/users/@me`.
4. The resulting Discord ID and display name are stored with the authenticated Pixel Everywhere member ID. The OAuth access and refresh tokens are *not stored*.
5. The member returns to the app. The link status refreshes automatically when the app regains focus or becomes visible; **Actualiser l'état** remains available as a fallback. The pending authorization button stays visible until the link succeeds, expires or the member changes. They can unlink from Pixel Everywhere at any time.

Database tables `member_discord_links` and `discord_link_states` are created on server startup. A Discord account cannot be connected to more than one member. Identity fields are read via protected routes; the callback never exposes tokens or secrets.

### Sign in to Pixel Everywhere with Discord (v1.7)

A member who has **already linked** their Discord account can choose **Se connecter avec Discord** from the member login panel:

1. PE starts an unauthenticated login attempt at `POST /api/members/discord/login/start`. The server stores SHA-256 digests of random OAuth state, `requestId` and `claimKey`, valid for 10 minutes.
2. The member authorizes only `identify` on Discord's official OAuth2 page using the existing registered callback.
3. The callback consumes the state, fetches Discord identity server-side and looks up an **existing** account association. It never puts a Discord token or PE session token in the callback URL or browser page.
4. The original PE app exchanges its device-held attempt credentials at `POST /api/members/discord/login/finish`. The server issues a regular **member-only** session **once**; retries after success and expired attempts fail.
5. The original member profile, points and messages remain unchanged. Username/password login still works. Unlinking revokes pending or completed-but-unclaimed Discord login attempts.

No PE account is auto-created, and no Discord role grants PE staff access. To enable this login for the first time, sign in using PE credentials and link Discord in the **Compte Discord** section.

If the app is killed during browser authorization, the login attempt needs to be restarted. Verify Android and Windows return-from-browser behavior and the manual **J'ai autorisé, vérifier** button.

### Staff-only Discord activity, phase 1

In **Admin / Staff Panel → Activité Discord**, an authenticated staff user can retrieve:
- Approximate guild member count and non-offline presence count (Discord REST API `GET /guilds/{guild_id}?with_counts=true`)
- Number of Pixel Everywhere users with a linked Discord account
- The eight latest readable channel announcements using the existing PDD bot
- Explicit informative errors if credentials, permissions or API access are missing

Results are held in a memory cache for 60 seconds. The dashboard intentionally **does not** claim real-time joins, departures, role changes or message totals: those require additional Discord Gateway instrumentation and server data collection.

## Termux configuration

On the **server only**, add the following to its private `.env` file; do not commit real values:

```dotenv
DISCORD_BOT_TOKEN=<already-existing-bot-token>
DISCORD_ANNOUNCEMENT_CHANNEL_ID=<announcement-channel>
DISCORD_GUILD_ID=<PDD-server-ID>
DISCORD_CLIENT_ID=<Discord-Developer-Portal-application-ID>
DISCORD_CLIENT_SECRET=<private-Discord-OAuth2-client-secret>
DISCORD_REDIRECT_URI=https://<stable-public-host>/api/discord/oauth/callback
```

In **Discord Developer Portal → Applications → OAuth2**, add the exact redirect URL above. An HTTPS public URL is required when running outside localhost. Use a stable ngrok domain or other HTTPS domain; if the ngrok URL changes, update the Discord portal and server `.env`.

**Important:** The existing Termux service is not upgraded by a GitHub commit alone. Keep the active server running while preparing the update, back up `data/pixel-everywhere.db` (and the private `.env`), then update its code and restart `npm start`. Do not overwrite the database or commit the OAuth client secret. The v1.7 client also needs to be built/deployed; older clients do not have the new menus.

## Required permissions and limitations

- The bot must already be in the PDD guild and have access to the announcements channel.
- The guild statistics are approximate, not a live activity log.
- The account linking page works in the v1.7 app client. Its OAuth callback opens in an external browser; users return manually and refresh.
- OAuth2 here only links an identity; it **does not** automatically grant Pixel Everywhere staff rights based on Discord roles.
- Staff authorization is checked by the existing server authentication middlewares. Hiding UI items by role is not authorization.
- No existing server data is deleted by this change except a requesting member explicitly unlinking their own Discord association.

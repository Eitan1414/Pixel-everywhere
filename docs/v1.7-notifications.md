# Pixel Everywhere 1.7 — Centre de notifications PDD

## Ce qui est implémenté

Le centre réutilise les **30 dernières annonces officielles Discord PDD** déjà récupérées par le bot existant. Aucune permission Discord supplémentaire n'est demandée au membre.

- Tuile **Notifications** sur l'accueil, avec une **cloche** et un badge dans la barre supérieure.
- Liste des annonces avec auteur, date, résumé et accès à la page Annonces.
- Filtres **Toutes / Non lues**, bouton **Marquer comme lu** et **Tout marquer comme lu**.
- Préférence **M'avertir des nouvelles annonces PDD dans l'application** enregistrée par compte PE.
- Synchronisation lorsque l'application est visible : au retour dans PE et toutes les 60 secondes. Affichage d'un bandeau dans l'app lorsqu'un nouvel élément est détecté.

**Limite importante : ce n'est pas un système de push lorsque l'application est fermée.** La première étape ne crée pas de notifications Android hors application. Les alertes natives des messages privés restent séparées. Une vraie diffusion en arrière-plan nécessitera l'enregistrement des appareils et un service push.

## Confidentialité et fonctionnement

La première consultation marque les annonces déjà existantes comme lues, pour ne pas déclencher de fausses alertes. Les nouvelles annonces deviennent ensuite non lues jusqu'à ce que le membre les ouvre ou les marque comme lues.

La base SQLite stocke deux tables :
- `member_notification_settings` : préférence d'annonces par `member_id`.
- `member_notification_reads` : identifiants Discord marqués comme lus par membre.

Les marqueurs de lecture âgés de plus de 90 jours sont nettoyés pendant les synchronisations. L'API n'accepte pour lecture que les IDs des 30 annonces réellement disponibles. Les annonces restent consultables même si le membre désactive les alertes : cette préférence n'efface pas les messages.

## Routes privées

Toutes les routes exigent `authenticateMember` et `requireActiveMember` :

| Route | Fonction |
| --- | --- |
| `GET /api/members/notifications` | Annonces récentes, état de lecture, compteur et préférence |
| `POST /api/members/notifications/read` | Marquer des IDs présents, ou `{ "all": true }`, comme lus |
| `PUT /api/members/notifications/settings` | Modifier `{ "announcementsEnabled": true / false }` |

La lecture Discord commune est mise en cache 30 secondes pour éviter un appel REST par membre.

## Configuration et tests

Le serveur nécessite déjà `DISCORD_BOT_TOKEN` et `DISCORD_ANNOUNCEMENT_CHANNEL_ID`. Le bot doit pouvoir lire les annonces. Aucune nouvelle variable d'environnement n'est nécessaire.

Tests : isolation entre deux comptes, contrôle des accès anonymes, première consultation sans faux non-lus, nouvel ID Discord, lecture individuelle et globale, préference désactivée, requêtes invalides et Discord hors ligne.

Les tests sont dans `test/notifications-v17.test.mjs`. Il reste à vérifier le rendu et les transitions foreground/background sur les véritables appareils Android et Windows. Avant de déployer, sauvegarder le fichier SQLite et les secrets du serveur.

**Aucun déploiement de production n'est effectué par cette PR.**

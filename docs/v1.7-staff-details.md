# Pixel Everywhere v1.7 — Étape 3 : fiches de modération

Implémentation des écrans « liste → détail → décision » inspirés des croquis 3–6.

## Fonctions ajoutées
- Bouton **Voir la fiche** sur les comptes staff, ouvrant un dialogue avec rôle, état, inscription, mot de passe temporaire et informations de liaison Discord à venir.
- Actions d'activation/désactivation et suppression avec **deuxième étape de confirmation**. Le serveur reste responsable des autorisations et de la protection des comptes.
- Bouton **Voir le profil** sur les comptes membres (administrateurs uniquement), présentant le solde, la plateforme et les dernières informations de présence ; le bouton « Modifier les pièces » renvoie au formulaire existant.
- Bouton **Voir le dossier** sur les rapports de bug et demandes XP. La fiche affiche le message et la date et exige une confirmation avant traitement.
- Rafraîchissement de l'état des dossiers via `GET /api/staff/alerts` avant toute décision.
- Aucun faux compte Discord « lié » : la fiche indique que cette fonction est à venir.

## Implémentation
- `web/v17-details.js`, `web/v17-details.css`, `web/v17-detail-model.js`.
- Ajout d'identifiants DOM stables aux cartes dans `web/main.js`.
- Extension des classes de section dans `web/v17-admin-panel.js`.
- Import optionnel dans `web/app-entry.js`.
- Tests du modèle : `test/v17-detail-model.test.mjs`.

Les API existantes sont réutilisées sans changement de contrat ni migration de base de données. Les informations envoyées par les utilisateurs sont affichées en texte et non injectées comme HTML.

## Vérifications manuelles nécessaires
1. Se connecter en administrateur et en modérateur ; vérifier les catégories disponibles.
2. Ouvrir et fermer les fiches de comptes, y compris le compte propriétaire protégé.
3. Vérifier l'activation et la désactivation d'un **compte de test**.
4. Vérifier l'annulation de toutes les confirmations, sans effet côté serveur.
5. Traiter un faux rapport et une conversion XP de test ; confirmer la mise à jour.
6. Vérifier le défilement sur téléphone, les lecteurs d'écran et les sessions expirées.

Ne pas fusionner avec `main` avant les vérifications fonctionnelles et de sécurité.

# Pixel Everywhere 1.7 — Admin Panel rework

## Scope: wireframes 1, 3, 4, 5 and 6

The second v1.7 increment builds a staff landing screen with welcome panel, category tiles, an optional detail-header and three-button navigation.

The existing legacy panels remain mounted in the DOM. Instead of rewriting sensitive operations, category cards click the existing `data-staff-tab` button, preserving server APIs and dialog behavior.

### Routes within the staff screen

- **Candidatures**: review dossiers, notes and accept/refuse dialogs.
- **Rapports**: pending bug reports and XP requests, isolated from the internal chat.
- **Discussions**: the existing staff conversation view, without the reports list.
- **Annonces**: app publication and changelog tools.
- **Comptes staff** (admin only): creation and activation/deactivation.
- **Utilisateurs** (admin only): existing presence and points-management tool.
- **Avis**: ratings dashboard.
- Other installed plugin tabs are discovered as extra categories.

## Authorization and current limits

The new UI checks which controls should be visible to the staff role. This is **not** a replacement for server-side authorization. All protected actions continue to use their original endpoints and middleware.

No OAuth2 Discord linking, Discord activity dashboard, tamagotchi changes, database schema changes, or account permission upgrades are included here. The server remains unmodified.

The panel is a first design pass from pencil sketches rather than final polished artwork; visual testing on a physical device is still needed.

## Testing

- `test/v17-admin-model.test.mjs` covers installed-tab filtering, moderators vs admins, report/discussion aliases and added plugin tabs.
- Project CI runs `npm test`, Vite build and native platform workflows.

Do not merge until platform CI passes and someone checks the admin panel navigation manually.
